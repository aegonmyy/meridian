    WI-4: withdrawal engine v2 — multi-spoke recall, claim-time pricing, cancel
    
    Replaces the Path 2/3 internals of _withdraw and settlement callbacks with the
    designed state machine:
    - PendingWithdrawal restructured: quotedAssets (reference only, not a promise),
      reservedIdle, arrivedAssets, pendingLegs. legToWithdrawal maps Path 3 recall
      leg ids back to their withdrawal.
    - Path 3 now plans legs across ALL active spokes (descending spokeBalances,
      RECALL_HAIRCUT_BPS-capped per leg) instead of recalling everything from a
      single 'best' spoke. Planning is a pure dry run before any state commits or
      CCIP dispatch — an uncoverable shortfall reverts the whole call
      (InsufficientRecallLiquidity), fail-closed, nothing locks. Fixes the old
      silent oversized single-spoke recall that could permanently strand shares.
    - Path 2 settlement now gated on _allSpokesFresh() — fixes settling on the
      first of several spoke reports while others were still stale.
    - Claim-time pricing: settlement recomputes previewRedeem(shares) at claim
      time via attemptSettlement/_attemptSettleWithdrawal, not the quote taken at
      request time. Solvency-gated per entry (never touches other entries'
      reservations); defers (SettlementDeferred) rather than reverting when
      insolvent right now — never poisons a token-carrying CCIP execution.
      WithdrawalRepriced emitted when payout differs from the quote.
    - New cancelWithdrawal(id) — WITHDRAWAL_TIMEOUT backstop, returns escrowed
      shares, releases the reservation. Late-arriving legs land as ordinary idle
      via the orphaned-arrival path (OrphanedRecallArrival vs RecallCompleted
      disambiguated via legToWithdrawal).
    - WithdrawalQueued now carries the withdrawal id (needed off-chain to call
      cancelWithdrawal/attemptSettlement — the hub has no other way to surface it).
    - Invariant suite: added redeemShares/attemptSettlement/cancelWithdrawal to
      the hub fuzz handler, plus the two new WI-4 global invariants (reservedAssets
      == sum of live pending reservedIdle; hub's escrowed share balance == sum of
      live pending shares) and an inTransitAssets-fully-reconciled invariant.
      Fixed two handler gaps this surfaced: fuzzed addSpoke could silently repoint
      an already-registered selector to a codeless address, permanently
      desyncing inTransitAssets; sumOfSharesEqualsTotalSupply didn't count the
      hub's own escrowed balance during a pending withdrawal.
    
    Divergence: a genuine two-real-spoke Path 3 settlement (neither spoke alone
    covering the shortfall) can't be faithfully simulated with the non-fork
    CCIPLocalSimulator (single hardcoded sourceChainSelector for every delivery —
    same constraint hit in WI-3). Multi-leg ordering is verified via dispatched
    SentToSpoke events instead; single-real-spoke settlement mechanics (actual
    arrived amount, claim-time pricing, cancel) are verified end to end.
