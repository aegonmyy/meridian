    WI-7: spoke-report sanity band + circuit breaker
    
    spokeBalances was previously written verbatim from any spoke message — a
    single compromised or buggy spoke could misprice the entire vault. Adds:
    
    - netSentToSpoke[selector]: += totalAmount on DEPOSIT sends, -= actual
      arrived (destTokenAmounts, never the payload's claimed amount) on
      CONFIRM_WITHDRAWAL arrivals, clamped at 0.
    - _applyReportedBalance: the single choke point every balance-carrying
      callback (CONFIRM_RECEIPT, CONFIRM_REBALANCE, REPORT_BALANCE,
      CONFIRM_WITHDRAWAL) now routes through. Upside-only band: reported <=
      netSentToSpoke * (10000 + MAX_YIELD_BPS) / 10000 + REPORT_DUST.
      Under-reporting (losses) always passes — it deflates share price, the
      safe direction — but emits an informational SpokeBalanceDropped event
      past a judgment-call LOSS_ALERT_BPS threshold (not one of the plan's
      named tunables; flagged for review).
    - On breach: never clamp (would corrupt pricing the other direction) —
      quarantine instead (quarantinedReports, SuspiciousSpokeReport event),
      leave spokeBalances untouched, pause deposits/withdrawals (new Pausable
      inheritance, gating only _deposit/_withdraw per Open Questions #4 — NOT
      deciding whether sendToSpoke/recallFromSpoke should also be gated).
      Owner resolves via acceptQuarantinedReport/rejectQuarantinedReport
      (tracks activeQuarantineCount so resolving one spoke doesn't unpause
      while another remains quarantined).
    - _applyReportedBalance never reverts — verified via a dedicated test that
      a token-carrying CONFIRM_WITHDRAWAL still delivers its tokens even when
      the accompanying report is quarantined. That test also surfaces a real,
      correct WI-4/WI-7 interaction: a quarantined (rejected) report leaves
      spokeBalances stale-high, which can make previewRedeem exceed currently
      available idle and correctly defer settlement rather than overpaying —
      documented in the test and this commit rather than treated as a bug.
